# Adaptive Memory 设计说明

## 目标

在保留 `independent-mode` 的前提下，新增 `adaptive-memory`。它模拟人处理新问题的方式：先暂时合上旧笔记，独立想出方案；再翻阅少量相关经验进行比较；只有真正学到新东西时，才向用户提出候选记忆，并在用户确认后交由平台保存。

这是一套平台无关的行为协议，不是假装清空模型上下文，也不直接控制任何平台的记忆系统。

## 给普通使用者的解释

把 Agent 的记忆想成一本笔记本。

- `independent-mode`：暂时合上笔记本，只看眼前的问题。
- `adaptive-memory`：先不翻笔记自己想一遍，再查看相关笔记，比较过去和现在，最后询问是否记下新经验。

例如：过去上班一直坐地铁，所以笔记里写着“地铁最快”。今天地铁停运了。`adaptive-memory` 不会直接照搬旧答案，而是先根据今天的情况重新规划，再检查旧经验，最后提出候选记忆：“地铁通常最快；停运时优先比较公交和打车。”只有用户确认后，这条经验才可以保存。

## 产品边界

### independent-mode

- 以显式触发消息作为上下文分界线。
- 触发前的聊天、本地记忆、历史任务、归档摘要和旧结论均不参与本次推导。
- 只使用触发后的用户输入、用户授权的当前文件、本轮获得的证据和通用知识。
- 不生成候选记忆，也不声称关闭或删除平台级记忆。
- 如果意外引用了历史内容，撤回该信息并基于当前证据重新推导。

### adaptive-memory

- 必须由用户显式触发。
- 第一轮推导不得读取或照搬旧记忆。
- 临时结论形成后，只检索与当前任务直接相关的少量记忆。
- 旧经验必须经过适用条件检查，不能因为“以前成功过”就直接复用。
- 只有发现实质变化时才生成候选记忆。
- 默认不自行保存、修改、失效或删除任何记忆。

## 触发方式

支持 Skill 语法和自然语言：

```text
$adaptive-memory
开启自适应记忆模式
先独立思考，再参考相关记忆
重新推导后再与过去经验对比
```

不支持 Skill 的 Agent 可以使用以下通用提示词：

> 本次任务启用自适应记忆模式。请先仅依据当前事实独立推导方案，在形成初步结论后，再检索与本任务直接相关的历史记忆进行对照。不得直接照搬旧结论。任务结束时，仅在发现新事实、旧结论失效、适用条件变化或明确的新偏好时，生成候选记忆；未经我确认，不得保存、修改或删除任何记忆。

“换个思路”“再想想”等模糊表达不构成授权，避免 Agent 擅自检索历史。

## 处理流程

1. **看清眼前问题**：提取当前事实、目标、限制和未知项。
2. **先自己想一遍**：抑制旧记忆，形成临时方案和依据。
3. **翻相关笔记**：只检索与任务直接相关的少量记忆，同时检查来源、可信度和适用条件。
4. **比较新旧经验**：决定继续采用、修正、弱化或推翻旧结论。
5. **完成当前任务**：输出基于当前事实的最终方案；不为追求新颖而强行改变正确答案。
6. **询问是否记住**：仅在产生实质变化时，展示最多三条候选记忆，等待用户决定。

找不到相关记忆时，流程停留在独立推导结果，不虚构历史经验。

## 记忆类型

- **工作记忆**：当前任务中的事实和限制，任务结束后自然释放。
- **情景记忆**：某次具体经历发生了什么。
- **语义记忆**：从经历中提炼出的稳定知识。
- **策略记忆**：特定条件下适合采用的解决方法。
- **偏好记忆**：用户明确表达、且可能持续有效的选择。

候选记忆的数据结构：

```yaml
action: add | reinforce | revise | weaken | invalidate
type: episodic | semantic | strategy | preference
content: 要保存的记忆内容
reason: 形成或改变的原因
evidence: 当前任务中的依据
scope: 适用场景
conditions: 成立条件
confidence: high | medium | low
source: 信息来源
created_at: 产生时间
last_confirmed_at: 最近验证时间
supersedes: 被替代的旧记忆标识
```

工作记忆不进入长期候选，因此不出现在可保存类型中。

## 记忆生命周期

- `add`：形成此前不存在的新经验。
- `reinforce`：独立证据再次验证已有记忆。
- `revise`：核心经验仍有效，但内容或适用条件需要调整。
- `weaken`：出现反例或长期没有验证，降低其影响。
- `invalidate`：当前证据明确推翻旧结论；保留版本关系，不等于物理删除。

检索时综合考虑相关程度、适用条件、可信度、新鲜度和验证次数。关键词匹配只能帮助发现候选，不能单独决定是否采用。

## 候选记忆交互

只有以下变化才触发候选：

- 出现此前没有的新事实；
- 找到可重复使用的新方法；
- 旧结论被当前证据推翻；
- 原有方法的适用条件发生变化；
- 用户明确表达长期偏好。

普通聊天、临时情绪、模型猜测和未经验证的推断不得进入候选区。

示例：

```text
候选记忆 #1

类型：策略记忆
操作：修正
内容：分析陌生视频时，应先检查实际画面，再推荐制作工具。
适用范围：视频效果分析
依据：仅凭常见流程推荐工具，可能被误认为读取了用户历史。
可信度：高
替代关系：修正旧的通用视频分析策略
```

用户可执行：

- `保存`：确认该候选可以交由平台写入。
- `修改：<新内容>`：按用户表述修订后再次展示。
- `忽略`：本次不保存，以后仍可在新证据下重新提出。
- `永久忽略`：记录拒绝规则，避免重复提出同类候选。
- `使旧记忆失效`：保留历史记录，但停止旧结论参与正常检索。

用户沉默不等于同意。平台不支持记忆写入时，只输出可复制内容，并明确说明尚未保存。实际删除必须由平台能力执行，展示具体对象、数量和影响后再次取得确认。

## 平台无关设计

通用 Skill 只定义四个接口概念，不假设具体实现：

- `retrieve(scope)`：读取与当前任务直接相关的记忆。
- `propose(candidate)`：向用户展示候选记忆。
- `commit(candidate)`：仅在用户确认后由平台适配器写入。
- `invalidate(memory_id)`：仅在用户确认后由平台适配器更新状态。

没有适配器时，前两步仍可用文本完成；后两步不得伪装成已经执行。未来可以分别为 Codex、Claude、Cursor 或 MCP 记忆服务实现适配器，通用 Skill 不绑定任何一家平台。

## 异常处理

- **没有相关记忆**：继续采用独立推导结果。
- **多条记忆冲突**：并列展示来源、条件和可信度，不擅自拼接。
- **当前证据与旧记忆冲突**：当前证据优先，生成弱化或失效候选。
- **来源不明**：标为低可信度，不写成用户事实。
- **平台不能写入**：输出候选文本，不声称保存成功。
- **用户拒绝候选**：立即停止，不换一种说法反复提出。
- **独立阶段意外引用历史**：撤回临时方案，重新执行独立推导。

## 验证标准

1. 没有历史记忆时仍能独立完成任务。
2. 有旧方案时，第一轮不会直接照搬。
3. 旧方案仍适用时，能重新说明采用依据。
4. 当前条件变化时，能提出不同方案。
5. 新证据推翻旧结论时，生成修正或失效候选。
6. 没有实质变化时，不生成候选记忆。
7. 用户未确认时，不声称已经保存。
8. `independent-mode` 启用前的聊天不会进入推导。
9. 用户授权历史材料后，只读取被授权的精确范围。
10. 平台无法写入记忆时，通用核心仍能完成推导和候选展示。

成功标准不是每次都给出不同答案，而是每次答案都能由当前事实重新推导；旧记忆只能作为第二阶段的参考证据。

## 本轮不做的内容

- 不实现平台记忆数据库。
- 不实现自动写入或自动删除。
- 不开发 MCP 服务。
- 不让 Skill 隐式触发。
- 不把模型训练知识或平台上下文描述成可物理清除的对象。
